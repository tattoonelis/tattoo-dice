# Tattoo Dice v2.53.0 — Implementation and Test Report

## Basis and scope

This build starts from the supplied and verified v2.52.24 working build. The existing dice engine, canonical composites, Roll and Shake motion, drop/fall lifecycle, shadows, Main VFX, header, counter and responsive layout were retained. The expansion is primarily isolated in `expansion.js` and a scoped v2.53 CSS section.

## Changed files

- `index.html` — Menu content, Favorite control, expansion screens and script entry.
- `style.css` — scoped Menu, Favorite, card-stack, Previous Roll, Guide-demo and AI Image styles.
- `script.js` — small bridge/events around the existing roll lifecycle; no dice-motion rewrite.
- `expansion.js` — local Favorites, card navigation, Previous Roll gesture and AI easter egg.
- `README.md` — release summary.
- `V2.53.0-IMPLEMENTATION-AND-TEST-REPORT.md` — this report.

## Previous Roll

`previousRoll` exists only as an in-memory variable in `expansion.js`. It is never stored in localStorage.

- Immediately before a normal Roll or Shake result is generated, the complete currently landed state is copied into `previousRoll`.
- A snapshot contains theme, count, ordered words, stable subject keys, Main/Random state and selected Main index.
- Theme, Main/Random, count or Reset changes dispatch a context-change event that clears `previousRoll`.
- A right-dominant Pointer Event gesture may start only over the dice stage, outside the browser-edge safety area and while the core bridge reports idle.
- The current and previous complete stage composites include the renderer and ground-shadow canvas. They live only inside a temporary clipped transition layer.
- Passing the proportional stage-width threshold restores the exact stored words without calling the randomizer, then clears `previousRoll`.
- Cancel, pointercancel, blur, resize and orientation change remove temporary layers and preserve `previousRoll`.
- The one-session hint is held by a non-persistent boolean and uses the existing notice frame.

## Favorites

Favorites are stored under `tattooDiceFavoritesV1` in localStorage and mirrored immediately in an in-memory array and card cache.

- The dedupe key combines theme, dice count, selected Main and ordered stable subject keys.
- Adding an existing state cannot create a second record.
- Removing a Favorite updates storage, cache, stack and heart status without a reward animation.
- The newest saved Favorite is index `0` and opens on top. Navigation changes only `currentFavoriteIndex`; it never rewrites storage order.
- The last remaining card cannot be swiped away, and right navigation cannot go beyond the newest card.

## Card and placeholder structure

Every cached card is one parent object containing:

1. one shared code-built card template/background;
2. a numeric 1/2/3 badge;
3. one parent hearts composition;
4. one heart object per subject, each with a replaceable artwork layer and an independent text layer;
5. an optional Main-only glow on the first heart.

The placeholder heart artwork is CSS-only. Later PNG artwork can replace `.favorite-card-heart-art` without changing storage, cache, text fitting or Pointer Event navigation. The fixed Favorite control also keeps outline, filled, pierced and flying-arrow layers separate for direct PNG replacement.

## Card Pointer Events

Only the current top card starts a gesture. Horizontal intent is separated from vertical movement before transforms begin. Drag distance follows the pointer, while the contact height controls a deliberately limited rotation. Left moves deeper into the fixed stack and right returns toward newer cards. Pointer capture, cancellation, lost capture, blur, resize and orientation cleanup are handled.

## Menu and lifecycle locks

The existing Theme modal is the Menu modal. Opening it does not change roll state. Theme selection still uses the original theme loader and performs the original scene handoff only when the Menu closes after a real theme change.

Expansion screens use a top-level blocking backdrop. The AI sequence additionally sets the core expansion lock, disables its close control and refuses close requests until the final typewriter letter. The final button is the only in-app exit after completion.

## AI Image easter egg

The selector reads only real Favorites. No Favorite means Generate is disabled. No AI model, network request, image service, account, tracking or additional storage was added.

The fake progress is monotonic, pauses at 56% with cycling `Generating artwork.` dots, then reaches 100% at approximately ten seconds. The clown and message cloud use replaceable DOM placeholders. The approved English text is stored once as an exact constant and typed with preserved paragraphs.

## Runtime tests performed in the in-app browser

- Fresh page load, splash completion and landed three-dice startup.
- No console errors or warnings after loading.
- Menu open/close and retained app state.
- Inline Theme navigation to locked Fantasy and existing PIN modal.
- Favorites add, persisted refresh state, card cache, two-card stack and horizontal swipe index.
- AI Image using an actual Favorite, monotonic fake load, reveal, exact complete message and delayed final exit.
- Normal Roll and the one-session Previous Roll hint.
- Right drag restoring the exact previous visible result without a new roll.
- Random 3 → 2 → 1 → 3 count paths on a 390×844 phone viewport.
- Fixed Main selection, VFX appearance and single-die disabled state.
- Reset back to Classic, Random and three dice.
- Guide opened from Menu with the existing tour lifecycle.
- Phone-sized layout and default desktop layout rendering.

Shake sensor input itself cannot be physically generated by the desktop test browser. The original sensor listener, live Shake animation and settle code are unchanged; its existing finish path was runtime-inspected and only receives the same before/settled state events as button Roll.

## Known limitations

- Favorite card, heart, flower/decoration, hand and clown assets are deliberate code placeholders pending final PNG artwork.
- The desktop browser cannot validate real DeviceMotion permission/sensor data; that requires a supported HTTPS phone/tablet test.
